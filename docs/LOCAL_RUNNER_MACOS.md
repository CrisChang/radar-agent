# macOS 本机自动执行（第三阶段）

这是一台电脑上的付款客户端。Vercel 继续托管收款接口；不需要另买服务器。
只适用于当前固定的 Arc 主网活动、原付款钱包和收款地址。第三阶段上限仍为
900 笔 / 0.209340 USDC，整个活动 1,000 笔 / 0.232600 USDC。
已经完成的付款不重做。仍按原 24 小时时间表运行，省去逐笔钱包弹窗。

## 1. 在原 Chrome 交接

1. 使用保存着付款记录的原 Mac 和 Chrome。先点“停止本机后续请求”，等待当前操作结束。不要清理本站数据。
2. 在 https://radar-agent-ivory.vercel.app/validation 连接原付款钱包、Arc 5042，点“只读核查全部付款与链上批次”，签署免费核查消息。
3. 等已有付款全部链上核实且金额差异为 0。若服务端已暂停，完成核查后点“核查完成后恢复原阶段”。
4. 刷新页面，找到“macOS 本机自动执行”，勾选同意接管，再点“准备本机接管包”。在钱包签署免费接管消息。
5. 接管确认后，点击独立的“下载接管文件 radar-local-handoff.json”链接。该文件包含原付款授权，仅保留在本人电脑，不要上传、发给客服或发送到聊天。接管后网页新付款入口被锁住，只读核查保留。重复点击按钮会下载相同原包。
6. 在同一区域下载 `radar-validation-runner-v2.cjs`，两个文件都放在“下载”目录。若浏览器添加了 `(1)` 等后缀，使用最新原包，通过 `--bundle` 指定其路径。

## 2. 在本机终端检查

需要 Node.js 22 或更新版本。如果 `node -v` 显示 command not found，请先从 https://nodejs.org/en/download 安装，重新打开终端。

```sh
node ~/Downloads/radar-validation-runner-v2.cjs --check
```

这一步仅校验接管包和服务端绑定，不读取私钥、不付款。下载页另有脚本 SHA-256；可以用
`shasum -a 256 ~/Downloads/radar-validation-runner-v2.cjs` 与下载页对照。

## 3. 本人启动

```sh
caffeinate -i node ~/Downloads/radar-validation-runner-v2.cjs --execute
```

终端显示固定付款范围后，输入 `RUN`，回车。随后私钥输入不会显示字符，粘贴专用测试钱包私钥后回车。
私钥只用于本机进程内存中的签名，不写入文件、环境变量、命令历史或网站；不发送给助手。
私钥自身仍能控制整个钱包，程序预算不是钱包级别的权限隔离，因此只使用已确认的小额专用测试钱包。

保持终端打开、Mac 接电且不要合盖。`caffeinate -i` 防止空闲休眠，不能保证合盖或手动睡眠后仍运行。
到计划时间会自动签名并提交；测试中的客户端重启由程序自动完成。
不要再从其他电脑或浏览器发起同一活动的新付款。

## 4. 停止、续跑及核查

- 按 Ctrl+C 停止新请求。已签授权不会因此撤销；原记录保存在 `~/.radar-agent-local/<runner-id>/`，不要删除。
- 正常停止后再次执行同一命令，重新由本人隐藏输入私钥，沿用原授权和账单续跑。
- 签名、网络结果或落盘结果不确定时程序停止，不会自动换 nonce 或重新建立付款。
- 意外断电可能留下 `.runner-lock` 或 `.pending`。程序会拒绝继续，先核查进程、原文件和线上账单，不要通过删除整个账单目录重来。
- 运行结束只代表请求已处理。回到网页做最终“只读核查全部付款与链上批次”，等待批次结算，检查付款数、场景数和金额差异。未完成、失败或场景证据不足仍会如实保留，不会自动算通过。
- 自动执行阶段新增的原授权在本机目录中，不能在浏览器通过重新签名补做同一笔；如需修复或补测，应沿用本机原记录。

## 实现与验证边界

- 服务端接管通过免费、5 分钟有效的钱包消息绑定 runner ID、接管包 SHA-256、固定计划和原预留笔数。
- Redis 原子切换要求阶段 3、有效预算、无在途结果、已有金额全部核实且差异 0。切换不增加笔数、金额或有效期。原网页即使持有旧报价也无法 claim 新付款。
- 接管包和原授权在本机导出与导入，服务端只接收公开绑定信息与接管消息签名。实际每笔支付仍按协议把该笔签名发送给固定收款接口。
- 独立父进程保存内存中的私钥，子进程只通过本机 IPC 请求精确的固定计划签名。签名前校验网络、合约、付款人、收款人、金额、到期时间、计划时间和唯一 nonce，并先持久保存签名保留记录。
- 本机账单目录权限 0700，文件 0600；不跟随账单符号链接；原授权先写入并 fsync，再提交 HTTP。并发补请求复用相同授权；重启场景真实创建新子进程。
- 运行锁保护同一 Mac；不能防止用户主动复制私钥和完整接管目录后在第二台电脑运行。不要复制执行目录或多机运行。
- 自动化测试均使用合成数据、本地 Redis 和模拟 HTTP，不验证真实密钥配置，也不在测试中发起主网付款。

构建：`npm ci` 后 `npm run build:local-runner`。提交生成的 public/downloads 文件及 SHA-256。
`--offline-check --bundle <合成文件>` 可离线验证安装包；开发和助手检查不得运行真实 `--execute`。


## v2 联网诊断（代理用户）

v2 会优先使用 `--proxy`，其次 HTTPS_PROXY／HTTP_PROXY 等环境配置，再读取 macOS 系统 HTTP 代理。
支付工作进程沿用同一代理，HTTPS 证书校验仍开启。不会因网络错误自动换授权或重发新付款。
原 v1 接管包、账单和签名继续使用，重新下载脚本即可，不需要重新接管。

```sh
node ~/Downloads/radar-validation-runner-v2.cjs --network-check
```

若代理软件只在浏览器中启用、没有设为系统代理，请从软件设置读取实际 HTTP／混合端口，再传给 `--proxy`。
例如端口确为 7897 时：

```sh
node ~/Downloads/radar-validation-runner-v2.cjs --check --proxy http://127.0.0.1:7897
caffeinate -i node ~/Downloads/radar-validation-runner-v2.cjs --execute --proxy http://127.0.0.1:7897
```

`--network-check` 不读取接管包或私钥；`--check` 只读核实接管。不要关闭 TLS 校验来绕过证书错误。


### v2.1 连接中断处理

`--network-check` 连续做三次公开状态查询。只读状态请求遇到连接中断或 HTTP 502/503/504 时，最多尝试三次；单次超时 10 秒，间隔 2 秒、4 秒。付款报价和提交不使用该网络重试逻辑，既有场景的原授权重放规则不变。
执行窗口会显示工作进程使用的代理，以及停止时的意图编号和请求步骤。接管包、本机账单、固定时间和金额限制沿用原值。
